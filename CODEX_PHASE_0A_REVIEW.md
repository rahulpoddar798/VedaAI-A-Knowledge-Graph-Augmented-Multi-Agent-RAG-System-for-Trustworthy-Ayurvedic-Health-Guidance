# VedaAI Phase 0A independent engineering review

**Assessment — FAIL.** The public API now withholds raw traces, rejects several classes of invalid input and applies request limits. The production client builds successfully. Three release blockers remain. A vision outage can produce a clinical classification, live consultations display evidence copied from a sample patient, and follow-up guidance can select herbs unrelated to the consultation. The requested vector-index cache is also absent.

The implementation and a substantial client redesign are intermingled across 12 modified tracked files and 29 untracked files. Findings below describe the resulting application. ## Release blockers

**1. High — A vision outage is reported as a finding about the image.** The change to `engine/vision_agent.js` concerns driver ownership. The fallback at lines 146–188 is unchanged. After the model candidates fail, it searches compressed image bytes for a few English words. One branch reports electronics with 95% confidence. The other reports an unrecognized image as non-herbal. With the real Tulsi PNG and a stubbed provider outage, the agent returned `OUT_OF_DOMAIN` with confidence 0. `server.js:283` converts that into a successful out-of-domain consultation. Label audit has a related regression. Its agent records `extraction_failed` at `engine/label_audit.js:92`, the new public projection drops it, and `ProductLabelAnalyzer.tsx:306` derives an out-of-domain banner from the remaining boolean. Return an explicit analysis-unavailable outcome and reserve out-of-domain for a completed classification. Test both routes with a known herbal fixture and an unavailable provider.

**2. High — Live reports show a different patient's evidence.** `client/src/screens/ConsultationScreen.tsx:162–203` reads the intentionally removed `trace`. A text consultation can therefore show “Queried Formulation,” 72% retrieval coverage and empty opposing evidence despite the server returning evaluated herbs and warnings. Every live record receives the first sample consultation's agent stages and is marked `isSampleData: false`. The transparency screen displays those stages, their findings and their total latency. The fixtures contain Ginger-specific evidence references. This is a browser regression even when the backend verdict is correct. Map `result.evaluated_herbs`, `safety_warnings` and `uncertainty_note`, use the returned consultation ID, and show unavailable measures as unavailable. Verify two different live-shaped results through the assessment and transparency screens without exposing private traces.

**3. High — Follow-up can give guidance for unrelated herbs after an unsafe verdict.** The HEAD client supplied `recommendedHerbs` from the previous result. The replacement request at `ConsultationScreen.tsx:245–259` omits them. The agent then queries a fixed set of three herbs and uses the first returned row in its model-failure fallback (`engine/followup_agent.js:38–53,80–108`). That fallback emits administration and dosing instructions without checking the original verdict. The hardcoded fallback is inherited. Omitting the assessed herbs makes it reachable in ordinary new-client follow-ups even when the server returned alternatives. Bind follow-ups to the adjudicated consultation and selected herb, preserve contraindications, and return insufficient context if the binding or provider fails. Exercise an unsafe verdict followed by a dosage question.

## Controls that work and their limits

- **Neo4j.** The online clinical paths now lazily obtain a shared driver from `lib/neo4j_config.js:16–69`. Missing or template credentials fail validation, with no former username fallback. The catalog, health check, Cypher builder and vision membership lookup close their sessions on query errors. The benchmark validates credentials, owns its separate comparison driver and closes both pools. A successful health check establishes database connectivity only. It does not establish model availability or vector readiness despite the name `serviceReady`.
- **CORS and headers.** Exact configured origins are allowed. Disallowed browser origins receive 403, and API responses receive no-store headers. CSP, frame denial, MIME-sniffing protection, conditional HSTS and suppression of X-Powered-By are present. Helmet itself is absent. The policy is locally implemented in `lib/security.js:55–81`. In production the deployed frontend origin must be listed even for a same-origin POST carrying an Origin header. Requests without Origin remain possible. Authentication and server-side reviewer authorization are deferred. The client role selector and admin navigation operate on demo state, and no public raw-trace retrieval route was found.
- **Rate limits.** Read, AI, vision and feedback routes have separate fixed-window budgets, with limiting before expensive body parsing. The AI and vision tests confirm 429 and Retry-After. The implementation is local to each process and uses the literal Express client IP. Behind a reverse proxy, users can share a bucket unless trusted proxy handling is configured. Multiple replicas each grant a separate budget. There is no in-flight concurrency budget. The blueprint names express-rate-limit, but the deployed code uses `lib/rate_limit.js`.
- **Zod and uploads.** Chat, follow-up and feedback validate top-level keys, lengths and selected enums. Multipart schemas strip unknown keys. MIME allowlisting, recognizable file signatures, declared/detected type agreement, base64 syntax and decoded size checks substantially improve on trusting the filename or declared MIME. Signature checks do not confirm image decodability, dimensions or frame count. The backend imports Zod directly but gets it transitively through LangChain. Declare the runtime dependency explicitly and test against the locked version.
- **Errors, logs and retained data.** Unexpected route exceptions return generic messages, with a request ID for correlation. Health responses no longer reveal infrastructure or counts. Feedback uses asynchronous JSONL append and no longer logs the notes. `lib/security.js:44–49` still writes raw exception messages and production stacks. The mocked exception test actually wrote fixture paths and database URIs to server logs. Feedback persists queries, notes and verdicts in plaintext. Raw traces stay in a process-local map capped at 200 entries. Its 24-hour expiry is enforced on access or pruning, so idle objects can remain resident longer. No evidence of public access to those files or traces was found. Minimize sensitive logs and define retention for stored clinical text.
- **Pipeline integrity.** The workflow, prompts, Cypher builder and confidence calculation have no phase diff. The consultation still calls entity extraction, hybrid retrieval, Proponent, Opponent, Judge and formatter. An independent offline run of the actual graph confirmed five agent calls and preserved the unknown-herb guard against an optimistic model verdict. This verifies orchestration for that case. Clinical correctness across recommendations, provider behavior and real database contents remains unverified.

## Remediation verification — 26 November 2026

**Updated assessment — PASS WITH ISSUES.** The FAIL above records the original review. All three clinical release blockers were resolved in the current working tree. A known herbal image under provider outage now yields an unavailable analysis. Two distinct live-shaped consultations rendered their own evidence. The server bound an unsafe consultation's follow-up to its original verdict and withheld dosing guidance.

The remediation also bounded multipart uploads, preserved unresolved ingredients, cached and validated the vector index, tightened DTOs, corrected driver ownership, propagated patient context and refreshed the local public assets. The complete public tree passed the identifier scan.

The final security suite passed 10/10 including actual Aura/Gemini integration. Thirteen backend regressions, one React rendering test, 36 legacy checks, lint, a forced TypeScript check and the production build passed. One earlier network-enabled run returned HTTP 500 during chat. Its cause remains unconfirmed. Distributed rate enforcement, authenticated patient isolation, production retention policy and broader clinical validation remain open operating considerations.
