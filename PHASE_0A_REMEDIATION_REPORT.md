# VedaAI Phase 0A remediation report

**Assessment — PASS WITH ISSUES for the Phase 0A working tree.** All three clinical release blockers have regression coverage. The application now distinguishes an unavailable analysis from a clinical finding, ties live evidence to the consultation that produced it, and binds follow-up answers to the server's adjudicated record. Remaining qualifications concern service reliability, conservative follow-up coverage, and the operating conditions described below.

Work stayed on `phase-0a-api-security`, based on `bebb423`. The starting tree contained 12 tracked modifications and 30 untracked files, including the independent review. The changes were applied to those sources in place. The generated asset refresh was local to this repository. No dependencies were installed or upgraded, no database was seeded, and no commit, push or deployment was performed.

## Operating limits and release conditions

- **Single-process scope.** Consultation IDs are random bearer references to an in-memory record for up to 24 hours or 200 entries. Expiry, eviction, restart or routing to a different worker can require a new consultation. Access controls for real clinician telemetry, authenticated patient ownership and persistent tenant separation belong to a later phase. Do not expose trace retrieval on the strength of the browser's role selector.
- **Clinical scope.** Follow-ups are deliberately conservative. They can restate scoped assessment facts. Ambiguous natural language, an unassessed substance or an unverified dose requires a new assessment or practitioner review. Calendar, profile and medication data reaching the service do not establish personalized interaction safety.
- **Availability and traffic.** Provider and database availability remain external. Rate and concurrency budgets apply within a process. Configure trusted proxy networks for the actual ingress and enforce shared limits before running multiple replicas. The manual security-header policy remains in use. No production proxy or distributed load test was performed.
- **Images.** Byte, part and field limits bound buffering. Type detection uses signatures. Full image decoding, pixel and frame validation were not independently certified. Successful model output still depends on the legibility and accuracy of the original label.
- **Retention and access.** Restrict application logs and the feedback directory to the service account and authorized operators. Set and enforce deployment-specific rotation and deletion periods for historical feedback and backups. Prior feedback records were left untouched. New records omit clinical queries, notes and verdict text. In-memory traces can contain sensitive clinical information.
- **Test boundaries.** The React check renders actual screens with two controlled records. Browser navigation, accessibility, arbitrary clinical queries, all languages and provider reliability under load were not independently certified. The live smoke test establishes the observed fixture outcomes only.
